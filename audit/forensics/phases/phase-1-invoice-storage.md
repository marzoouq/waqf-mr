# المرحلة 1 — إغلاق قراءة ملفات الفواتير (مقفلة ✅)

## المشكلة

سياستان واسعتان على `storage.objects` لحزمة `invoices`:
- `Authenticated users can view invoices` — دور `public`، شرط `bucket_id` فقط.
- `Role-based users can view invoices` — تمنح المستفيد/الواقف قراءة كل الفواتير
  بلا ربط بـ `invoices.file_path` ولا `is_fiscal_year_accessible`.

كلتاهما تتجاوز بوابة التنزيل الخادمية بالكامل.

## الإصلاح الفعلي

1. هجرة تُسقط ستة أسماء سياسات قديمة محتملة بشكل idempotent.
2. حارس `DO $$ ... RAISE EXCEPTION` داخل الهجرة نفسها: يفشل الترحيل إن بقيت أي
   سياسة `SELECT` على `storage.objects` يشير شرطها إلى `invoices`.
3. القرار المعماري المثبَّت: **صفر سياسة قراءة** على الحزمة. التنزيل حصراً عبر
   `invoice-file-url` (service role) التي تتحقق من الجلسة، الدور، السنة المالية
   المنشورة، حجب IP، وحد المعدل 30/دقيقة، ثم تُصدر رابطاً موقّعاً 120 ثانية
   وتُسجّل كل محاولة في `access_log`.

## التحقق

- الهجرة نُفِّذت بنجاح والحارس لم يُطلق استثناءً (أي القاعدة نظيفة فعلاً).
- `src/test/storagePolicyRegression.test.ts` — 3 اختبارات ناجحة:
  يعيد بناء حالة كل سياسة عبر 398 هجرة ويؤكد أن لا سياسة قراءة نشطة، ويؤكد
  الإسقاط الصريح للاسمين المعروفين، ويؤكد وجود المصادقة والرابط الموقّع في
  وظيفة الحافة.
- ملاحظة: تنفيذ الإصلاح على الإنتاج مرتبط بالمرحلة 0 (النشر).
