# المرحلة 3 — جرد دوال SECURITY DEFINER (مقفلة ✅)

## المشكلة

195 ملاحظة من linter قاعدة البيانات بلا جرد يفصل المقصود عن غير المقصود، أي
لا يمكن لأي مراجع أن يميّز الخطر الحقيقي من الضجيج.

## النتيجة بعد الفحص

| المؤشر | القيمة |
|---|---|
| الملاحظات بعد هجرة 2026-08-25 | 85 (من 195) |
| دوال `anon`-executable | 5 — كلها مقصودة وموثّقة |
| دوال `authenticated`-executable | 79 — محمية داخلياً بـ `has_role` |
| عروض `SECURITY DEFINER` | 1 (`contracts_safe`) — مقصود لإخفاء PII |

الدوال العامة الخمس: `get_public_stats`, `log_access_event`, `check_rate_limit`,
`get_rate_limit_count`, `lookup_by_national_id` — كلها أسطح ما قبل المصادقة
تُعيد أرقاماً مجمّعة أو عدّادات أو قيماً مُقنَّعة فقط.

## القرار الهندسي

**لا يُسحَب `EXECUTE` من `authenticated`.** الدوال تحتاج `SECURITY DEFINER`
لتجاوز RLS التقييدي على الجداول المالية، وPostgREST لا يوفّر دوراً وسيطاً، فسحب
الصلاحية يعطّل التطبيق. الحماية الصحيحة هي فحص `has_role` داخل كل دالة — وهو
قائم. لذلك تحذيرات `0029_*` **مقبولة بوعي** وموثّقة، لا مُتجاهَلة صمتاً.

المشغّل `auto_revoke_anon_execute` يمنع نموّ السطح العام تلقائياً.
