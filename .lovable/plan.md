## الهدف
حل سبب فشل النشر بدون تغييرات عشوائية، والتمييز بين:
- عطل مؤقت في Lovable Cloud / بيئة النشر.
- مشكلة إعدادات تمنع البناء أو المزامنة.
- مشكلة في تغييرات حديثة مثل migrations أو hooks أو ملفات حماية النشر.

## الخطة

1. **فحص حالة Lovable Cloud**
   - التحقق من حالة Backend في بيئة الاختبار والبيئة الحية إن أمكن.
   - إذا كانت الحالة غير صحية أو تعطي خطأ داخلي، لا نعدّل الكود ونوصي بإعادة المحاولة/إعادة تشغيل backend عند الحاجة.

2. **فحص إعدادات النشر الأساسية**
   - التأكد من وجود متغيرات Vite العامة المطلوبة للنشر.
   - التأكد أن التغيير السابق حول `.env` لم يكسر حماية الأسرار أو يمنع تضمين القيم العامة اللازمة للبناء.
   - عدم تعديل `.env` أو مفاتيح Lovable Cloud المحمية.

3. **فحص آخر تغييرات قد تؤثر على النشر**
   - مراجعة ملفات الحماية المضافة/المعدلة مؤخراً مثل pre-commit/pre-push و CI إن وجدت.
   - مراجعة آخر migration مضاف فقط للتأكد أنه لا يحتوي SQL يمنع تطبيق schema عند النشر.
   - عدم إصلاح أو تغيير أي security findings أخرى خارج نطاق المشكلة.

4. **تحديد مسار الإصلاح حسب السبب**
   - إذا السبب بنية Lovable Cloud: أطلب موافقتك على restart backend ثم نعيد التحقق.
   - إذا السبب ملف إعدادات/حماية نشر: أعدّل أقل عدد ممكن من الملفات لإزالة مانع النشر فقط.
   - إذا السبب migration: أضيف migration تصحيحي آمن بدل تعديل التاريخ، مع الالتزام بـ RLS و GRANT.

5. **التحقق بعد الإصلاح**
   - فحص الإشارات المناسبة فقط: حالة backend، وجود الإعدادات، وخلو التغيير من مانع واضح للنشر.
   - ثم تطلب إعادة النشر من واجهة Lovable لأن النشر نفسه يحتاج إجراء المستخدم.

## ملاحظات مهمة
- لن أستخدم أو أعرض أي أسرار.
- لن أعدّل ملفات محمية مثل `client.ts`, `types.ts`, `.env`, أو `supabase/config.toml`.
- سأبقي التغيير محدوداً بسبب أن الخطأ الحالي يظهر كـ internal publishing error وليس طلب ميزة.
