## الخطة: تطبيق هجرة pgmq يدوياً على Live

### المشكلة
خطأ متكرر كل 5 ثوانٍ في Live: `relation "pgmq.q_auth_emails" does not exist` بسبب cron job (jobid=8) يستعلم عن طوابير بريد غير موجودة.

### الخطوات

1. **تطبيق SQL على Live يدوياً** (عبر Cloud View > Run SQL مع تحديد Live):
   ```sql
   SELECT pgmq.create('auth_emails');
   SELECT pgmq.create('transactional_emails');
   ```
   - آمن تماماً: `pgmq.create` idempotent، لا يؤثر على بيانات أو صلاحيات أو RLS
   - لا يحتاج نشر التطبيق

2. **التحقق بعد التطبيق**:
   - استعلام `pgmq.meta` للتأكد من ظهور الطابورين
   - مراقبة `postgres_logs` لمدة دقيقة للتأكد من توقف الخطأ
   - فحص cron job (jobid=8) أنه يعمل بدون أخطاء

3. **عدم لمس** الهجرات الأخرى المعلقة:
   - `20260527132751` (NOT NULL على payment_invoices) — تفشل بسبب 18 صفاً NULL
   - `20260527144824` (SECURITY DEFINER) — تحتاج مراجعة منفصلة
   - تبقى في Test فقط ولن تُنشر

### النتيجة المتوقعة
- توقف خطأ pgmq نهائياً في Live
- النظام يصبح قابلاً للنشر العادي مستقبلاً (المشاكل الأمنية الأخرى تُعالج في خطة مستقلة)

### ملاحظة
هذه الخطة **لا تتطلب تغييرات في الكود** — فقط تنفيذ SQL يدوي على Live من قبلك عبر لوحة Cloud. بعد تأكيدك أنفذ التحقق من النتائج.
