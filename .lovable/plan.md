# فحص جنائي عميق للمستودع — خطة مراحل مُقفلة ببصمة

الفحص السابق كان إحصائياً سطحياً (عدد ملفات/جداول/اختبارات). هذه الخطة تُنتج تفتيشاً جنائياً حقيقياً لكل ملف ومجلد وهوك ومسار وتعارض، **وتُقسّم إلى 7 مراحل لا تُقفل أي واحدة منها إلا بعد إصلاح فعلي مُتحقَّق منه، ببصمة إقفال موثّقة**.

المبدأ: لا تصريح دون دليل (مسار + سطر + مخرجات أداة). وإن كان البند نظيفاً يُكتب "0 نتائج" لا يُسكت عنه.

## ما تم التحقق منه فعلياً قبل هذه الخطة

- `src/` = 1405 ملفاً، 35 barrel، 18 سكربت تدقيق، 21 أمر npm.
- لا مسار مكرر حرفياً في `src/routes/*.tsx` (0 تكرار في `path="..."`).
- أسماء ملفات مكرّرة عبر مجلدات (`dashboard.ts`, `invoices.ts`, `support.ts`, `useIncomeComparison.ts` …) تحتاج تمييز المتعمَّد من التكرار.
- 28 مجلد Edge Function مقابل إعدادات `config.toml` تحتاج مطابقة دقيقة.
- 48 علامة دين تقني (`TODO/FIXME/HACK/@ts-ignore/eslint-disable`) في 43 ملفاً.
- ملف واحد فقط يستخدم `: any`، واختباران معطّلان (`skip`/`todo`).
- تقرير الاتفاقيات الحالي: 0 حرج، 7 تحذيرات (6 `NoToastInDataHooks` + 1 `HooksLayering` في `hooks/page/auth/useOAuthConsent.ts`)، و4 `HexColors`.

ما لم يُتحقق منه يُعالَج كخطوة فحص، لا كاستنتاج.

## نظام الإقفال ببصمة (Gated Phase Closure)

لكل مرحلة ملف توثيق خاص في `audit/forensics/phases/PH-<n>-<slug>.md` يتضمّن:

1. **النطاق** — ما فُحص بالضبط، بالأوامر المستخدمة حرفياً.
2. **النتائج** — جدول: المعرّف، الخطورة، الملف:السطر، الوصف، الدليل.
3. **الإصلاح** — لكل نتيجة: ما تم تغييره فعلياً (diff مرجعي) أو قرار "مقبول عن وعي" مع مبرر موقّع.
4. **إثبات الإصلاح** — إعادة تشغيل نفس أداة الفحص وإظهار انتقال العدد من N إلى 0.
5. **مصفوفة التحقق** — أنواع + ESLint + سلسلة audit + كل الاختبارات، بالأرقام قبل/بعد.
6. **بصمة الإقفال** — كتلة موقّعة تلقائياً في نهاية الملف:

```text
─── CLOSURE SIGNATURE ───
phase:        PH-3-routes
status:       CLOSED
findings:     14 → 0 open (12 fixed, 2 accepted-with-reason)
typecheck:    0 errors
eslint:       0 errors
audit gate:   0 critical / 0 GAP
tests:        2195 passed / 0 failed
files_hash:   sha256:<هاش محتوى الملفات المعدّلة في المرحلة>
evidence:     audit/forensics/phases/PH-3-routes.md
closed_at:    <ISO timestamp>
─────────────────────────
```

**قاعدة المنع**: سكربت جديد `scripts/forensics/phase-gate.mjs` يرفض إقفال المرحلة إذا:
- بقيت نتيجة واحدة بخطورة Critical/High غير مُصلحة، أو
- الفحص المُعاد لم يعطِ 0، أو
- أي بوابة (typecheck / ESLint / audit / tests) ليست خضراء، أو
- الهاش المسجّل لا يطابق الملفات الحالية (أي تلاعب أو إقفال بلا تغيير حقيقي).

عند الرفض تبقى المرحلة `OPEN` ولا تبدأ المرحلة التالية. لا يوجد إقفال "شكلي": البصمة تُحسب من الملفات المعدّلة نفسها، فالإقفال بلا إصلاح مستحيل تقنياً.

يُضاف أمر واحد: `npm run forensics` للفحص، و`npm run forensics:close -- PH-<n>` للإقفال المحكوم.

## المراحل

### PH-1 — الملفات والمجلدات
جرد كامل (حجم/أسطر/طبقة/آخر تعديل/مستهلكون)؛ الملفات الميتة عبر تتبّع فعلي لرسم الاستيراد من `main.tsx` (لا regex فقط)؛ الصادرات الميتة؛ الأصول غير المرجوعة في `public/` و`assets`؛ التكرار الحقيقي بتشابه المحتوى؛ المجلدات الفارغة/أحادية الملف/المخالفة لتصنيف `audit/architecture-map.md`.

### PH-2 — الهوكات
جرد 361 هوكاً بطبقته ومستهلكيه؛ غير المستخدم والمستخدم مرة واحدة؛ **تعارض الوظيفة** (هوكان ينفّذان نفس الاستعلام/الحساب)؛ انتهاكات الطبقات بما فيها التحذيرات السبعة القائمة؛ اشتراكات Realtime بلا cleanup أو بأسماء قنوات مكرّرة (نفس صنف الخطأ الذي وقع سابقاً)؛ `queryKey`/`staleTime` المتعارضة؛ deps ناقصة.

### PH-3 — المسارات والصلاحيات
مصفوفة موحّدة: المسار ← الملف ← أدوار `pr()` ← `routeRoles.ts` ← `routeRegistry.ts` ← `navigation.ts`. كشف: مسار غير مسجّل أو مسجّل بلا مسار، تعارض أدوار بين الحارس والسجل، صفحات يتيمة، عناصر قائمة لمسار غير موجود، تظليل `*`، وتغطية `MaintenanceGuard`/`IpBlockGuard` على كل الأشجار.

### PH-4 — المعمارية والتعارض
تنفيذ كل قاعدة اتجاه في خريطة الطبقات كفحص فعلي وإضافة الناقص؛ كشف **الاعتماد الدائري** في رسم الاستيراد والـ barrels؛ تمييز `utils` (نقي) عن `lib` (بحالة)؛ تجاوزات الحجم 200/180؛ المكوّنات الهجينة؛ و48 علامة دين تقني تُصنَّف (يُصلح / يُوثّق / يُحذف).

### PH-5 — قاعدة البيانات والخادم
لكل جدول: RLS، سياسات لكل عملية، مطابقة `GRANT` للسياسات، فهارس المفاتيح الأجنبية، أعمدة يتيمة. الدوال: `SECURITY DEFINER` بلا `search_path`، دوال غير مستدعاة، مشغّلات متضاربة على نفس الجدول. مطابقة ثلاثية: الكود ← القاعدة ← `types.ts`. الـ 28 Edge Function: مطابقة `config.toml`، `getUser()`، Zod، CORS، معالجة الأخطاء. ترتيب الهجرات وما نُقض منها لاحقاً.

### PH-6 — الأمان والخصوصية
أسرار في الكود، `console.*` متبقٍ، تسجيل بيانات شخصية، `dangerouslySetInnerHTML`، مسارات تخزين عامة، سياسات واسعة. فحص 74 تبعية (ثغرات + غير مستخدمة + انزياح). تشغيل linter القاعدة وماسح الأمان بنتائجهما كاملة دون تلطيف.

### PH-7 — الجودة والاختبارات والأداء
الملفات الحرجة مالياً/أمنياً بلا اختبار (لا مجرد عدّ)؛ الاختباران المعطّلان والاختبارات التي لا تتحقق من شيء؛ أحجام chunks، صفحات غير lazy، استيرادات ثقيلة في الحزمة الأولى؛ ثم مصفوفة التحقق الكاملة كأرقام نهائية.

## التفاصيل التقنية

- أدوات الفحص سكربتات Node في `scripts/forensics/` قابلة لإعادة التشغيل (تحليل استيرادات فعلي، لا تقرير لمرة واحدة).
- القاعدة تُفحص للقراءة فقط عبر كتالوج النظام (`pg_policies`, `pg_indexes`, `pg_proc`, `pg_trigger`) وماسح الأمان؛ أي إصلاح قاعدة يتم بهجرة مستقلة معروضة عليك قبل التنفيذ.
- التغييرات في مرحلة PH-1..PH-4 تشمل حذف كود ميت — تمرّ عبر `scripts/deletion-gate.mjs` القائم (أنواع + اختبارات + audit) قبل أي حذف.
- `phase-gate.mjs` لا يُضاف إلى `pre-push` إلا بعد إقفال المراحل السبع، لتجنّب إغلاق البوابة على نتائج قديمة.
- الترتيب إلزامي: PH-1 → PH-7، ولا انتقال قبل بصمة إقفال صحيحة.

## ما لن تحصل عليه

الفحص يقيس الكود والبنية والصلاحيات — لا يقيس صحة الأرصدة والتوزيعات التاريخية في القاعدة؛ تدقيق صحة الأرقام المالية على البيانات الحقيقية خطة منفصلة.
