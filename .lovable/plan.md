# خطة العزل الكامل للملفات بقرار الناظر

## الهدف
لا يصل أحد إلى أي ملف (فواتير، سندات صرف، وثائق الأرشيف، الأصول) إلا بإذن صريح يمنحه الناظر من لوحة التحكم. الوضع الافتراضي: منع تام (fail-closed).

## ما سيراه الناظر
شاشة جديدة «صلاحيات الملفات» في الإعدادات، فيها لكل فئة ملفات ولكل دور (محاسب، مستفيد، واقف، دعم):
- القراءة/المعاينة: مسموح / محجوب
- التنزيل: مسموح / محجوب
- الرفع: مسموح / محجوب
- الحذف: مسموح / محجوب

وفوق ذلك إذن فردي اختياري على مستوى الملف (نشر وثيقة لمستفيد محدد أو حجبها عنه)، وسجل يوضح من حاول الوصول ومن رُفض.

## البروتوكول (حارس قبل وبعد)
1. **خط الأساس:** جرد كل سياسات `storage.objects` الحالية في الاختبار والموقع الحي وحفظها كدليل.
2. **أحمر:** اختبارات تثبت التسريب الحالي (مستفيد غير مأذون يسرد/يقرأ/ينزّل) — يجب أن تفشل أولاً.
3. **تنفيذ أدنى:** إسقاط كل السياسات المتجاوزة والمكررة، واستبدالها بسياسة واحدة لكل عملية تمر عبر دالة قرار مركزية.
4. **أخضر:** نفس الاختبارات تنجح: غير المأذون مرفوض، المأذون يصل، الناظر يصل دائماً.
5. **كسر متعمد:** تعطيل الدالة مؤقتاً لإثبات أن الاختبار يكشف الخلل، ثم الاسترجاع.
6. **المصفوفة الكاملة:** tsgo، conventions، audit:forensic، test، test:edge، quality:dup.

## النطاق حسب الفئة
- **الفواتير:** تبقى بلا أي سياسة قراءة مباشرة؛ التنزيل حصراً عبر بوابة الخادم، وتضاف إليها مراجعة قرار الناظر.
- **سندات الصرف:** المعتمدة فقط، وبإذن الناظر للدور/المستفيد.
- **وثائق الأرشيف:** حسب الفئة + علامة النشر + الإذن الفردي.
- **الأصول (شعار، قوالب):** الملفات اللازمة للعرض العام فقط تبقى مقروءة، ويُمنع سرد محتوى الحاوية.

## خارج النطاق
لا مساس بالبيانات المالية أو المسميات، ولا بملفات المصادقة المحمية.

## ملاحظة النشر
أي سياسة جديدة لا تصل الموقع الحي إلا بالنشر مع الموافقة على تحديثات قاعدة البيانات؛ بعده نعيد الفحص على الموقع الحي.

## التفاصيل التقنية
- جدول `file_access_rules` (bucket, category, role, can_read, can_download, can_upload, can_delete) وجدول `file_access_grants` (object_path, beneficiary_id/user_id, allow/deny, expires_at) مع GRANTs وRLS: إدارة للناظر فقط.
- دالة `can_access_file(bucket, path, action)` SECURITY DEFINER مع `search_path` ثابت: admin دائماً true؛ deny الفردي يغلب؛ ثم grant الفردي؛ ثم قاعدة الدور؛ وإلا false.
- سياسات `storage.objects` لكل حاوية/عملية تستدعي الدالة فقط، وحارس `DO $$ RAISE EXCEPTION` في الهجرة يفشل إن بقيت سياسة لا تمر عبرها.
- `invoice-file-url` و`createSignedUrl` للأرشيف والسندات يحترمان الدالة نفسها.
- هوك عبر `createCrudFactory` + صفحة في `hooks/page/admin`، واختبار `storagePolicyRegression` يُوسَّع ليعيد بناء الحالة ويتأكد من عدم وجود أي سياسة متجاوزة.
- اختبارات قاعدة بيانات باستخدام حسابات اختبار لكل دور للتحقق من الرفض والقبول.
