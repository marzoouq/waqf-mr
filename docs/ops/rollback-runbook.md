# خطة الرجوع السريع بعد النشر (Rollback Runbook)

آخر تحديث: 2026-08-25

## 1. متى نُنفّذ الرجوع

| الإشارة | الحد | الإجراء |
|---|---|---|
| أخطاء عميل (`client_error`) في `access_log` | > 20 خلال 10 دقائق | رجوع فوري |
| `invoice_download_denied` لمستخدم مصرّح | أي حادثة | تحقيق ثم رجوع إن استمر |
| فشل تحميل الصفحة الرئيسية (`/`) في الإنتاج | مرة واحدة | رجوع فوري |
| `unauthorized_access` غير مبرَّر | ≥ 3 خلال 10 دقائق | رجوع + حجب IP |

## 2. خطوات الرجوع (الواجهة)

1. من محرّر Lovable: افتح سجل الإصدارات (History).
2. اختر آخر إصدار موثَّق أنه يعمل، ثم **Restore**.
3. اضغط **Publish → Update** لإعادة نشر الإصدار المُستعاد.
4. تحقّق بـ `node scripts/post-deploy-verify.mjs` (انظر §4).

> الواجهة فقط تعود بالنشر. **الهجرات لا ترتد تلقائياً.**

## 3. خطوات الرجوع (قاعدة البيانات)

الهجرات تراكمية ولا تُلغى بالنشر. لأي هجرة مشكوك فيها:

1. لا تحذف بيانات — اكتب هجرة تصحيحية جديدة (forward fix).
2. للسياسات: أعِد إنشاء السياسة السابقة صراحةً بهجرة جديدة.
3. لا تُسقط أعمدة أُضيفت حديثاً قبل التأكد من عدم وجود بيانات فيها في الإنتاج.
4. بعد التصحيح: `npm run check:migrations` يجب أن يمر بلا فجوة.

## 4. الفحص بعد النشر

```bash
node scripts/post-deploy-verify.mjs            # فحص المسارات العامة في الإنتاج
npm run check:migrations                       # لا انفصال هجرات
npx vitest run src/test/storagePolicyRegression.test.ts
```

ثم من لوحة الناظر: `/dashboard/diagnostics` → «الفحوصات» (تشغيل كامل) و«🔔 التنبيهات»
للتحقق من صفر حوادث حرجة مفتوحة.

## 5. المراقبة والتدقيق

- **سجل التدقيق**: `access_log` (+ `access_log_archive`) و `audit_log` غير القابل للتعديل.
- **قواعد التنبيه** المفعّلة للإخفاقات الأمنية:
  `invoice_download_denied`, `policy_denied_spike`, `rls_violation`,
  `ip_blocked_event`, `unauthorized_access_spike`, `client_error_spike`.
- الحوادث تُجمَّع في `alert_incidents` مع إشعار داخلي وبريد للناظر.
- Sentry مربوط بـ `logger` لالتقاط الاستثناءات في الإنتاج.
