# قائمة فحص يدوي — ثبات قراءة الإشعارات

تُجرى هذه الاختبارات على **Desktop + Android Chrome + iOS Safari** بعد كل نشر يلمس
ملفات الإشعارات.

## 1. الثبات الأساسي (السيناريو المُبلَّغ)

1. افتح التطبيق بحساب لديه إشعارات غير مقروءة.
2. افتح جرس الإشعارات → اضغط **"قراءة الكل"**.
3. تأكد أن:
   - الـ Badge اختفى فوراً (Optimistic).
   - لا تظهر `toast.error`.
4. أغلق التطبيق كلياً (PWA: سحب من المهام / متصفح: إغلاق التبويب).
5. أعد الفتح من جديد بنفس الحساب.
6. **النتيجة المتوقعة:** الإشعارات تبقى مقروءة، الـ Badge صفر، لا تكرار.

## 2. القراءة الفردية

1. افتح الجرس واضغط إشعاراً واحداً.
2. النقطة الزرقاء + لون الخلفية يختفيان **فوراً**.
3. أعد فتح الجرس → الإشعار يبقى بحالة مقروء.

## 3. سلوك فشل الشبكة

1. فعّل وضع **Offline** من DevTools.
2. اضغط **"قراءة الكل"**.
3. **متوقّع:** `toast.error('تعذّر تحديث حالة الإشعارات')` + الـ Badge يعود إلى قيمته السابقة.
4. أعد تشغيل الشبكة وأعد المحاولة → ينجح طبيعياً.

## 4. حذف الإشعارات

- اضغط (×) على إشعار → يختفي فوراً + يبقى محذوفاً بعد إغلاق وفتح التطبيق.
- اضغط **"حذف المقروءة"** → كل المقروءات تختفي فوراً.
- مع وضع Offline: يظهر `toast.error('تعذّر حذف الإشعار')` ويُستعاد.

## 5. الفحص عبر الصفحات

تنقّل بين هذه الشاشات وتأكد أن عدّاد الجرس متّسق ولا يُعيد عرض إشعارات قُرئت:

- `/dashboard` (ناظر / محاسب)
- `/beneficiary/notifications` (مستفيد)
- شاشات `properties`, `contracts`, `invoices`, `distributions`
- التبديل بين تبويبات لوحة الناظر بسرعة (Audit, Settings, …)

## 6. على الجوال (PWA مُثبّت)

- إشعار push يصل → يفتح التطبيق على الإشعارات.
- إغلاق التطبيق من المهام ثم إعادة الفتح → الحالة محفوظة (لا "ارتداد").

## 7. تحقق DB (اختياري للناظر)

من **لوحة Cloud > Run SQL** على Test:

```sql
SELECT COUNT(*) FILTER (WHERE is_read) AS read_count,
       COUNT(*) FILTER (WHERE NOT is_read) AS unread_count
FROM public.notifications
WHERE user_id = '<USER_ID>';
```

يجب أن يزيد `read_count` بعد كل عملية "قراءة الكل".
